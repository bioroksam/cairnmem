# cairnmem

给**长期存在**的代理用的可验证记忆层。

三层：记忆存线索、知识库存已抽象过的全文、档案存原始材料。
它不追求检索得更准，它只做一件事：**让每条结论都能回到原始材料**。

---

## 它解决什么

一个连续存在数月甚至数年的代理，最大的敌人不是遗忘。

遗忘是干净的，你知道自己不知道。真正麻烦的是**摘要覆盖了原文**：

- 每压缩一次上下文，「当时发生了什么」就被改写成一句话
- 那句话进入下一轮压缩，变成摘要的摘要
- 几轮之后，记忆自洽、流畅、且与现实脱节

cairnmem 的应对不是更强的模型，是**分层**：

| 层 | 存什么 | 会不会被改写 |
| --- | --- | --- |
| 记忆 | 结论、判据 | 会，而且必须一直改 |
| 知识库 | 已抽象的全文 | 派生品，随时重建 |
| 档案 | 原始材料 | **不可改写** |

最后一行是关键。只要原始材料还在，结论就能重算；一旦只剩结论，漂移就没有上限。

## 安装

`@bash
pip install cairnmem      # 尚未发布到 PyPI 时用：pip install -e .
`@

零运行时依赖，只要 Python >= 3.9。

## 三步跑起来

`@bash
cairn init                      # 生成 cairn.json
cairn index                     # 建索引
cairn find "39 页 字数"          # 碎片 -> 全文
`@

配置只有两件事：材料在哪、档案在哪。

`@json
{
  "workdir": "~/.cairn",
  "sources": [{ "kind": "markdown", "path": "~/notes" }],
  "archive": { "path": "~/corpus/plain.txt", "marker_regex": null },
  "scopes": { "thesis": ["毕业设计", "docx"] }
}
`@

## 命令

| 命令 | 作用 |
| --- | --- |
| `init` | 生成配置模板 |
| `index` | 扫材料重建索引 |
| `find` | 关键词找全文 |
| `get` / `list` | 打全文 / 列条目 |
| `lint` | 体检：哪些条目以后查不到账 |
| `archive-build` | 建档案词频 |
| `gap` | 档案有、知识库没有的缺口队列 |
| `verify` | 回档案验证某个词，零命中就是假设错 |
| `markers` | 找出「做过工程 / 吃过大亏」的条目 |
| `dig` | 顺着一条结论回档案挖原始记录 |

`markers` + `dig` 是主力：知识库给线索，档案给原始记录。

## `lint` 查什么

五项，每一项对应一种具体的失效：

| 检查 | 含义 |
| --- | --- |
| 无锚点 | 正文里没有任何可定位标识符，以后只能信、不能验 |
| 外部来源不全 | 引了 URL 却没有抓取日期 / 快照，链接烂了等于没留 |
| 死路径 | 正文里的绝对路径已不存在 |
| 标题被截断 | `title` 是 `body` 的硬截断（生成侧缺陷） |
| 日期不符 | 正文里的日期与条目自身日期不一致 |

外加一项「标题同族」：同一项目多篇多版本，合并前先认。

**工具只负责把问题算出来，修不修由写那条的人决定。**

## 设计取舍

**为什么不用向量 / embedding**
在一个一百到几百条、查询与目标共享术语的库上，字符 n-gram tf-idf + 余弦实测 R@3 0.89；
换成需要训练的方式，收益被「专有名词在通用语料里共现太少」吃掉。
当年鉴数据涨到词表覆盖 70% 以上、查询以同义改写为主时，这条结论应该重测。
工具留了接口，但默认不走。

**为什么不切词**
二元组在「术语查询 + 短文档」下优于词切分，且不引入词典依赖。
切词会把 `gtlcore-1.2.3.2-fix3` 这类专有词切碎。

**为什么档案是「一份纯文本」**
为了低耦合。cairnmem 不认任何工具的日志格式，只要求你把材料导出成纯文本，
再给一个可选的分段正则。分段正则留空时整份材料算作一段。
它不 import 任何框架，不读任何私有数据库。

**为什么只做关键词**
可解释、可复现、零依赖。每个分数都能手算，每次结果都能重跑。

## 它会失效的地方

- **同义改写**：换个说法来问，关键词索引就掉命中率。那时需要别名表或向量。
- **库大了**：几百条之外没验证过。
- **档案要你自己给**：cairnmem 不替你把会话、网页、日志导出来。
- **抽象这一步还是人做的**：工具能算出缺口，不能替你写结论。
